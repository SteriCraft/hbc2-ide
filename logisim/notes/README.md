# Logisim: status of the circuits (2026-11-15)

The whole HBC-2 CPU is drawn in Logisim-evolution from TTL chips: **146 chips** for the CPU, plus **12** for the I/O mailbox card (iod). Every module is generated by a Python script and tested against the emulator, which is the reference. The whole CPU runs programs in Logisim with a trace identical to the emulator's, cycle for cycle. What is left is in [TODO.md](TODO.md).

## Using the circuits

All commands run from `logisim/`. They need Python, Logisim-evolution (`C:\Program Files\logisim-evolution\logisim-evolution.exe`), and the emulator built in release mode (`cargo build --release` in `hbc2/`). [tools.md](tools.md) has every tool in detail.

### Look at a circuit

- Open `cpu.circ` in Logisim-evolution. `main` is the whole CPU; every module file is loaded as a library.
- Open a module alone, for example `circuits/alu/alu.circ`.
- To see a program run, open the bench `circuits/cpu/test_cpu.circ`. Its boot ROM holds the program.
- **Don't edit the generated `.circ` files by hand.** They are rewritten from `designs/<module>.py`: edit the script, then run it.

### Rebuild and test a module

```
python designs/<module>.py           # rewrite the .circ, then run circcheck and conventions
python designs/<module>.py --test    # also run the emulator's vectors in Logisim (hbc2 vectors <module>)
python designs/<module>.py --png     # also draw a PNG of the layout
python tools/timing.py --section all [--duty 45|50|55]
```

### Compare a program's trace with the emulator

`tools/cputest.py` runs the whole CPU headless in Logisim, from power-up through the boot (65,548 steps). It writes a trace of what the pins show, and compares it with the emulator's trace of the same program (`hbc2 trace` / `hbc2 compare`). The emulator side is `tools/emutrace`, built once with `cargo build --release` in that folder.

```
python tools/cputest.py run tests/cpu/allops.has            # one program on the CPU bench
python tools/cputest.py run tests/iod/mbx.has --bench iod   # the CPU + the mailbox card + a test MCU
python tools/cputest.py suite --random 5 --jobs 4           # tests/cpu/*.has + 5 random programs
python tools/cputest.py mutants                             # each known wiring bug must fail
python tools/cputest.py cycles <results dir>                # steps per instruction vs cu-cycles.md
```

- A run takes about 3 to 5 minutes, mostly the boot.
- Use `--jobs 4` at most, and don't run other Logisim tests at the same time.
- The results go to `%TEMP%/hbc2_cputest*/<name>.{logisim,emu}.csv`.
- Benches: `cpu` (the default), `iod`, `iod_eager`, `iod_reset_tx`, `iod_reset_rx`, `iod_reset_evt`.
- A run checks four things: no bus contention (E) on any pin, the control lines at their pulled levels during reset, every boot-copy write, and an identical trace.

### Later: compare with the hardware

The cards are first tested one at a time on breadboards, with a test rig: an Arduino Mega driving 595 / 165 shift-register chains. The rig replays the **same vectors** as the Logisim tests (`hbc2 vectors <card>`).
- The wiring of each card to the rig is in `rig/<card>.map`, checked by `python tools/rigmap.py check <card>` or `all`.
- The rig hardware and the replay procedure: [test-rig.md](test-rig.md).
- What only a scope can show: [breadboard-checks.md](breadboard-checks.md).
- **Not written yet:** the Mega's replay firmware and `tools/replay.py` ([TODO.md](TODO.md)).
