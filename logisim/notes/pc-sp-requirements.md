# PC, SP and address path: requirements from other sections

What the other sections need from the PC / SP / address section (PC, SP, the 16-bit address adder, the address latch; not designed yet). Add each new requirement here, with the section that needs it and why.

Times are in ns from the rising edge of `clk` that starts the step, max at 85 °C (chips.md "Delays"); the step is 500 ns.

| # | Needed by | Requirement | Why |
|---|---|---|---|
| P1 | registers (2026-11-04; a hard requirement, Gianni the same day) | **An address latch** (16 bits, edge-triggered on `clk`, holds when not loaded, no gated clock) between the address adder and the address bus. A memory or I/O access whose address comes from registers takes one step to load the latch from `regs_a`:`regs_b` (+ V2 for mode 4), and the access happens in the following steps with the registers free. For IN and OUT the latch takes **00 in the high byte** and `regs_b` in the low byte (the port number: R2 for IN, R1 for OUT), as cpu.rs does (`address_bus = port as u16`). | STR mode 4 needs R1, R2 and R3 at once, and the register section has two read ports. It also breaks two loops through the transparent 74HCT670: LOD R3 with R3 = R1 or R2, and IN R1, R2 with R1 = R2, where the register being written would also be the address (registers-decisions.md section 1, D6). |
| P2 | registers (2026-11-04) | Take **`regs_a` as the high byte and `regs_b` as the low byte** of 16-bit register values: R1:R2 addresses (mode 4, + V2), JMP/JMx/CAL Reg16 (→ PC), WSP Reg16 (→ SP). They are valid **195 ns** into the step (with bus loading: the address path's inputs are part of that load, 1 input per bit estimated), so the adder and the latch or register setup must fit in the remaining 305 ns. | The register section reads R1 on port A and R2 on port B (registers-decisions.md D9). |
| P3 | registers (2026-11-04) | **Drive SP high, then SP low, onto `bus_data`** (tri-state, one byte per step, enabled by the control unit) for RSP. Valid by **325 ns** into the step, with the data bus's load (about 420 pF), and held until the clock edge (control-requirements.md C10). | RSP writes SP into R1 and R2 through the register write path, whose only data input is the data bus (registers-decisions.md D6, D7). |
| P4 | registers (2026-11-04) | Never load the address latch, PC or SP from `regs_a` / `regs_b` in a step where a register is written (`regs_we_n` low): port A shows the new value while /WE is low. | The 670 write is transparent (registers-decisions.md D3). |
