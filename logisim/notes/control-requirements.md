# Control unit: requirements from other sections

What the other sections need from the control unit (designed in [cu-decisions.md](cu-decisions.md)). Add each new requirement here, with the section that needs it and why.

| # | Needed by | Requirement | Why |
|---|---|---|---|
| C1 | ALU (2026-11-04) | Drive `alu_op` (alu-report.md table) and give the ALU a full 500 ns step: operand register clock-to-Q + ALU + setup = 327 ns at 85 °C max. Put 01 on `alu_b` for INC/DEC (with the register/bus section, registers-requirements.md R1). | alu-decisions.md D9, D16, F1 |
| C2 | flag register (2026-11-04) | Drive `flags_op` and `flags_bit_val` from the flags_op table (flags-decisions.md). Schedule the **two-flag events as two steps**: interrupt entry = `1010` with 0 (I), then `1111` with 0 (H), overlapping the pushes and the vector fetch; invalid instruction = `1010` with 0 (I), **then** `1111` with 1 (H) (order changed 2026-11-05, cu-decisions.md Q7: the halt loop must never sample I = 1). `flags_op` must be valid 229 ns before the clock edge at 85 °C max. | The register writes one flag per clock; Gianni chose two steps over a fifth multiplexer source. |
| C3 | flag register (2026-11-04) | **STI delay**: I reads 1 right after STI, but interrupts must be ignored until the next instruction has run (`interrupt_delay` in cpu.rs). | Belongs to the control unit, not the register. |
| C4 | flag register (2026-11-04) | Drive `flags_oe_n` low only for PSF, when nothing else drives the data bus. | PSF (flags-decisions.md); bus side in registers-requirements.md R2. |
| C5 | registers (2026-11-04) | Drive the register section's controls (registers-decisions.md "Interface") from a register clocked by `clk`: they change only at the edge and are valid 41 ns after it (the timing assumes it). In every step: **exactly one source on bus A** (port A: `regs_a_sel` with a real index, or the A operand latch with port A off: `regs_a_sel` = 11, `regs_cu_bank_n` = 11) and **exactly one on bus B** (port B: `regs_b_sel` ≠ 11; or `regs_b_sel` = 11 with one of `regs_b_lat_oe_n`, `regs_const_oe_n`). `regs_cu_bank_n` = 00 is forbidden. **`regs_a_bus_oe_n` is never low while `regs_we_n` is low.** At most one driver on `bus_data` (`regs_a_bus_oe_n`, `regs_res_oe_n`, `flags_oe_n`, memory, IOD, SP/PC). | Tri-state buses; the bus-A driver is the only combinational path from a register back to the write data (registers-decisions.md D5, D6). |
| C6 | registers (2026-11-04; generator chosen by Gianni the same day) | **Clock generator**, both phases from one 4 MHz oscillator (`osc`, 50 % duty) and a **74HCT74**: FF1 clocked by `osc`, D = /Q, gives **`clk`** (2 MHz, Q) and `clk_n` (/Q); FF2 clocked by `osc` inverted, D = `clk`, gives Q2; **`clk_wr_n` = NAND3(`clk_n`, `osc`, Q2)** (74HCT10, its second gate inverts `osc` for FF2). `clk_wr_n` is low from the clk fall (250 ns) to the next osc fall (375 ns), glitch-free: one NAND input moves at a time, and Q2 masks the osc rise at 500 ns. At 85 °C max with no minimum delays: /WE (after the register section's one OR) falls 215–345 ns, rises 340–435 ns, pulse ≥ 30 ns. `clk` drives every flip-flop's clock and nothing else. **`clk_mem_wr_n` = FF2's /Q2** (added 2026-11-05, ir-mem-decisions.md M1): low from the osc fall at 125 ns to the one at 375 ns, the RAM's write strobe (WE# = `clk_mem_wr_n` OR `mem_we_n`; pulse ≥ 174 ns at 25 °C, `timing.py --section mem`); the 670 writes keep `clk_wr_n`. **Changed 2026-11-05 (cu-decisions.md section 12):** the 74HCT10 is NRND, so `clk_wr_n` = (`osc_n` OR Q2_n) OR `clk` (2 gates of a 74HCT32; `osc_n` from a 74HCT14 gate, which also clocks FF2); same window, pulse unchanged, end of the pulse up to 56 ns later (latest rise + hold 484 ns at 25 °C). **A 74HCT541 buffers** `clk`, `clk_wr_n` and `clk_mem_wr_n` (the same delay on all three), and the oscillator is specified at **45–55 % duty** (Q9). | The 74HCT670 writes on a level, so /WE must start and end inside the step, away from the clock edge (registers-decisions.md D7). One source: the two phases can't drift apart. |
| C7 | registers (2026-11-04) | **Reset sweep** after `rst_n` (the 670 has no reset): 9 steps with `alu_op` = AND (1000), B = the constant 00 (`regs_b_sel` = 11, `regs_const_oe_n` = 0, `regs_const_0` = 0), `regs_res_oe_n` = 0 from step 1; step 0 only fills the result latch; steps 1–8 write index 0–7 (`regs_a_sel` = 11, `regs_cu_idx` / `regs_cu_bank_n`, `regs_we_n` = 0). No flags stored, no memory access. Tested by `hbc2 vectors regs`. | The emulator clears every register on reset (`Cpu::reset`); AND with 00 gives 00 whatever port A shows (registers-decisions.md D8). |
| C8 | registers (2026-11-04; inverted bit 2 decided by Gianni the same day) | **Instruction register**: provide `R1` (byte 1, bits 5..3), `R2` (byte 1, bits 2..0) and `R3` (V1, bits 2..0) as outputs of a register clocked by `clk`, stable for the whole instruction once fetched, **and the inverse of bit 2 of each** (`regs_r1_2_n`, `regs_r2_2_n`, `regs_r3_2_n`) from the same register: invert before the latch (three inverters on the IR's D side, during the fetch), not after it. | `regs_r1`, `regs_r2`, `regs_r3` select the registers; R3 is only meaningful in mode 4 (`Instruction::r3`). Not bit 2 selects words 4–7; an inverter after the latch would add 28 ns to the critical read path (registers-decisions.md D5). |
| C9 | registers (2026-11-04) | **Step order**, because the latches load on every edge (registers-decisions.md D2 and the step table in section 5): the memory read (or the V1 fetch of a RegImm8 instruction) comes in the step **right before** its ALU step; the register write (or the memory write of INC/DEC/NOT) of an ALU result comes in the step **right after** the ALU step; the flags are stored at the end of the ALU step, never of the write step. MOV R1, R2 = AND R2, R2 (flags not stored) then a write of R1. Register I is index 4: `regs_a_sel` = 11, `regs_cu_idx` = 00, `regs_cu_bank_n` = 01 (push of I on interrupt entry and INT, load of I on interrupt entry and IRT). | Free-running latches, no enables (D2); shared port A / write index (D3). |
| C10 | registers (2026-11-04, revised the same day) | **Data bus timing for register writes**: whatever is written into a register from `bus_data` (memory, IOD, SP, the V1 fetch for MOV R1, imm) must be valid **335 ns** into the step at max 25 °C (the pass criterion; 325 ns at max 85 °C), **322 ns with the oscillator's 45–55 % duty** (2026-11-05, cu-decisions.md Q9: the limit every section now uses) and hold until the clock edge, **with the data bus's load** (about 420 pF when estimated, 372 pF since the address section is counted on its circuit (+33 / 42 ns on a 6 mA bus driver at 25 / 85 °C, +49 / 65 on a 4 mA output, against the 50 pF datasheet figures); `timing.py --section regs`). Memory writes get their data at 273 ns (a register) or 128 ns (the result latch). | 670 setup D 15 ns before the earliest /WE rise at 340 ns (registers-decisions.md D7). Was 235 ns, taken against the /WE fall. |
| C11 | address section (2026-11-04) | Drive the section's controls (addr-decisions.md A2) from the clocked control register: `addr_base_sel` + `addr_base_oe_n` (2), `addr_off_sel` + `addr_off_oe_n` (2), `addr_inv`, `addr_cin`, the 3 load enables (`addr_lat_ld_n`, `addr_pc_ld_n`, `addr_sp_ld_n`), the 6 output enables (`addr_lat_oe_n`, `addr_pc_oe_n`, `addr_sp_oe_n`, 2 each). At most one driver on `bus_addr` per byte (the latch, the IOD, the pending port latch) and at most one of PC high, PC low, SP high, SP low on `bus_data` (with C5's other drivers). P4 applies: no load from `regs_a` / `regs_b` while `regs_we_n` is low. The step formulas are in addr-decisions.md section 2. | One adder for every address; tri-state buses. The 377 /E needs 12 ns setup and **5 ns hold** after the edge (A4). |
| C12 | address section (2026-11-04, Q2) | **Interrupt entry sequence**: push I, PC low, PC high (latch, SP := SP − 1 before each write; the last push step also does latch := 0000), **then** raise INR and wait for INT low; in the **vector step** the latch outputs are off (hardware) or its low byte only (software), RAM and IOD are not enabled by the CPU, I is written from `bus_data` (hardware only), and latch, PC := FE00 + 2p; then read → V1, latch := PC + 1; read → V2; latch, PC := Vx (addr-decisions.md A8). The IOD must drive `bus_addr` by **237 ns** into the vector step (25 °C; 170 at 85 °C). | Pushing first keeps the IOD's port and data on the buses for one step only (no latch to hold them for 3 steps). |
| C13 | address section (2026-11-04, Q1) | **Pending software interrupt port latch**: 1 × 74HCT377 + 1 × 74HCT541, loaded by INT **from `bus_data` while V1 is fetched** (changed 2026-11-05, cu-decisions.md Q4: INT takes 4 steps instead of 6, and no longer shows 00:V1 and I on the buses), cleared when taken, drives the `bus_addr` low byte in the software vector step; I is not written there (the data is I when the interrupt is taken, as the emulator now does). | INT stays pending until I is set and no hardware interrupt goes first. |
| C14 | address section (2026-11-04, Q4) | The **IR loads V1 and V2 from `bus_data` in any step**, not only during the fetch: RET and IRT put the return address there (high byte → V1, low → V2), the interrupt entry puts the IVT entry there. | PC never loads from the data bus: saves 4 × 157 and 4 data bus inputs. |
| C15 | address section (2026-11-04, Q5) | **Invalid instruction**: the fetch incremented PC for each byte read; undo it with PC := PC − 1 (`addr_base_sel` = PC, `addr_inv` = 1, `addr_cin` = 0, `addr_pc_ld_n` = 0) once per byte read (1 or 2 steps) before halting, so PC stays on the instruction (cpu.rs `stops()`). | The fetch can't know the mode is invalid before reading it. |
| C16 | address section (2026-11-04, A1) | **Reset word**: while `rst_n` is low, hold `addr_base_sel` = 11, `addr_base_oe_n` = 01, `addr_off_oe_n` = 11, `addr_inv` = `addr_cin` = 0, `addr_pc_ld_n` = `addr_sp_ld_n` = 0, every output enable off (all buses undriven), from the reset line itself (e.g. the control register cleared or its microcode address forced by `rst_n`), not by a sequence. With the section's two 74HCT08, every `clk` edge during reset gives SP = FE00, PC = 0000. `rst_n` must last at least one `clk` edge and be **released synchronously to `clk`** (the reset generator, C17). The latch is not reset: the first fetch starts with latch := PC. | The 377 has no clear or preset; Gianni requires the reset values to come from the reset line (addr-decisions.md A1). |
| C17 | address section (2026-11-05, Gianni's review of addr-report.md item 2) | **Reset generator**: an RC (power-up, with a push button across C and a diode to discharge C at power-off) → **74HCT14**, two inverters in series (a clean edge, active low) → the asynchronous clear of both flip-flops of a **74HCT74** (a second one; C6's is full), clocked by `clk`, FF1 D = VCC, FF2 D = FF1's Q. **`rst_n` = FF2's Q**: it goes low at once (asynchronous assert) and rises only just after a `clk` rising edge (synchronous release, 35 ns max at 85 °C, before the control register's 41 ns, C5), at least two edges after the RC releases, so it always covers at least one `clk` edge; two stages also absorb metastability. FF1's Q (`rst_early_n`, one edge earlier) is for the control unit: the step in which `rst_n` is first high must already carry the first fetch word, not the reset word (C16), or PC would load FE00 (e.g. the next-word logic forced to the reset word by `rst_early_n`, or the control register's outputs gated by `rst_n`). The oscillator runs during reset. | The address section's reset is synchronous (addr-decisions.md A1): the 377s sample the reset word and the 08s at the edge, so `rst_n` must not change near one. The flag register's /MR doesn't care. |
| C18 | IR + memory (2026-11-05, ir-mem-decisions.md section 7) | **IR loads and decode.** Drive `ir_b0_ld_n`, `ir_b1_ld_n`, `ir_v1_ld_n`, `ir_v2_ld_n` from the control register (the 377 samples /E at the edge: 12 ns setup, 5 ns hold, as C11). Fetch byte 0 (latch := PC, then the RAM read with PC := PC + 1); byte 1 only if the opcode takes operands; V1 and V2 as the mode's length says (isa.rs `DECODE`: invalid opcode = 1-byte NOP whatever the mode bits; no-operand opcode: stops if byte 0's mode bits ≠ 00; listed mode: `AddrMode::length`; otherwise stops after 2 bytes, then C15). Bytes past the length are not loaded and keep their old values: never use a field past the length; for a 1-byte instruction **ignore `ir_mode` bits 1..0** (stale; the microcode for a 1-byte opcode must not depend on them). | The IR has no decode and no clear (ir-mem-decisions.md section 2; tested with stale bytes by `hbc2 vectors ir_cpu`). |
| C19 | IR + memory (2026-11-05) | **Memory strobes**, from the control register, only in these combinations (`mem_re`, `mem_oe_n`, `mem_we_n`, `mem_wbuf_oe_n`, `mem_rom_oe_n`): idle / I/O / vector step 0 1 1 1 1; RAM read 1 0 1 1 1 (counts as the `bus_data` driver, C5); RAM write 1 1 0 0 1 (the data source drives `bus_data` for the whole step); boot copy 1 1 0 1 0. RW and IE go to the IOD connector; **RE and IE are never both 1.** The RAM writes while `clk_mem_wr_n` is low (C6): the address must not change in the step (the latch loads only at the edge, P1). | mem's interface (ir-mem-decisions.md section 4); a second driver on `mem_d` or `bus_data` fails the tests. |
| C20 | IR + memory (2026-11-05, Gianni's answer 1) | **Boot loop** after the reset (C16, C17) and the register sweep (C7): one step latch := PC (0000); then, every step, latch, PC := PC + 1 (`addr_base_sel` = PC, `addr_cin` = 1) with the boot-copy strobes (C19), until **`addr_cout` = 1** in a copy step (the step that copies FFFF: PC wraps to 0000); then the first fetch (latch = PC = 0000 already). 65,536 copy steps, 33 ms. **As built (2026-11-05, cu-decisions.md Q8):** the microcode can't branch on `addr_cout` in the same step, so it tests it one step later (`cout_q`): 0000 is copied a second time, then one step PC := PC − 1, then the first fetch; reset to first fetch 65,548 steps (32.8 ms). No interrupt is taken before the first fetch. Every reset copies again. | The ROM image is the emulator's power-on RAM (`Machine::power_on`); `addr_cout` is the last 74HCT283's carry out (addr, 2026-11-05). |
| C21 | IR + memory (2026-11-05, Gianni's answer 7; refines C12) | **Hardware interrupt timing**: **INR = 1 for exactly one step** (step n), which is **the last push step** (2026-11-05, cu-decisions.md Q5; the IOD only reacts at the edge ending it, so its contract is unchanged); step n + 1 is the vector step (the IOD drives `bus_addr` 00:p by 237 ns and `bus_data` by 335 ns); no waiting, no WAIT line. INT is sampled only at instruction boundaries and changes only just after a `clk` edge (the IOD is synchronous to `clk`, iod-requirements.md). | The manual's handshake is a fixed one-clock answer. |
| C22 | IR + memory (2026-11-05) | **I/O steps**: IN and OUT are one step each with IE = 1 and the latch showing 00:port (P1): IN with RW = 1 (the IOD drives `bus_data` by 335 ns; R1 written in that step, C10); OUT with RW = 0 (R2 onto `bus_data`, `regs_a_bus_oe_n`; the IOD captures it on the rising edge of `clk_wr_n`). The RAM strobes are idle (C19). | iod-requirements.md. |
| C23 | control unit (2026-11-05, Gianni's answer 4) | **The control unit is microcoded**: EEPROMs indexed by opcode, mode and step (plus the few state bits it needs: interrupt pending, reset, …), with a **pipeline register on their outputs** (the control register of C5, clocked by `clk`). The decode of C18 (length, invalid opcode = NOP, invalid mode = stop) is in the EEPROM contents, not in gates. | Gianni's decision; the IR gives the raw `ir_op` and `ir_mode`. |
