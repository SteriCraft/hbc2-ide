# Library (step 8) — how it works

(Moved out of ROADMAP.md 2026-10-31. Read only when working on this part.)

- `compiler/lib`: `include/` (cpp gets `-I` in both drivers), `lib.has` (asm part), `src/*.c` compiled by `hbc2_cc::build_library(dir)` with units 100+ → `dir/library.has` (includes lib.has + compiled files). Programs: crt0, runtime, library.has, own files. See lib/README.md.
- `asm/screen.has`, `asm/terminal.has` (rewritten 2026-11-11): the native display's commands sent straight to the mailbox (`scr_byte`, `scr_recv`, `scr_stream` for PUTS of 255 at most), interrupts off per call; `screen_colors` = the terminal's colours (default 0x1E), restored after `screen_putc`/`screen_write`/`screen_clear`. Cursor, wrap, scroll, blink: the I/O processor. `_display_port` (runtime/devices.has) = 0: every routine sets C. `time.has`: `lib_get_time` (GET_TIME, C if protocol < 2 or month 0), the tick (`lib_tick_start` points the display port's vector to `lib_tick_handler`, VSYNC on; 32-bit `lib_ticks` adds `i - last`), `_clock`, `_delay`.
- Device detection (since 2026-11-11): crt0 runs `cli`, clears the .bss, calls `dev_init` (`lib/asm/devices.has`, shared with the assembly template: INFO, device table in .bss, 2 s timeout per byte as a 24-bit loop of 38 cycles a turn, unset device vectors -> `dev_ignore`), then `crt0_devices` (`runtime/devices.has`: the four port variables, the EEPROM by product ID 0x0004), `sti`, `main`. `runtime/devices.has` includes `../lib/asm/devices.has` itself, so crt0 + runtime assemble without the library (helpers tests).
- EEPROM (step 13; the target and `boot.has` were removed on 2026-11-11, the `lib_eeprom_*` routines stay): `boot.has` = `_start` (wait for `_eeprom_port`, copy EEPROM $0x0200..`__program_end` to RAM, `jmp crt0_init`) + devices.has + init.has. Device variables fixed at $0x01FA-$0x01FF in boot.has (auto `.data` goes after ALL code → would be overwritten by the copy); crt0.has declares them auto. `build_program` assembles for RAM in both cases (`Program` keeps RAM addresses → IDE breakpoints/line maps work), `check_boot` errors if `_start`/`boot_*`/`devices_*` labels pass $0x01FA, `not_copied` warns about fixed code/data past the end. Library: `lib_eeprom_seek` (b:a:c:d address → ports, C = refused), `lib_eeprom_range` (+ length in [x:y]), `lib_eeprom_next` (address ports + 1 by reading the port latches).
- Terminal from C: `lib_term_start` (hbc2.has) = the first output clears the screen and shows the blinking cursor (no prompt, unlike term_init; without a native display output does nothing). putchar/puts in asm, getchar/gets in C (static `next`), printf in asm (`asm/printf.has`, since 2026-11-03; it calls `_putchar`).
- Tests: programs.rs runs every program with monitor + RTC + keyboard (`MachineConfig::default()`), `name.screen` = expected text screen (32 columns, the cells' characters through `hbc2_core::charset::to_char`; the cursor is not in the cells), `name.keys` = typed once `term_kbd_ready` = 1, one key per 20 000 ticks.
